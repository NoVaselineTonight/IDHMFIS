§ 1Getting Started

System Requirements

  • OS: Windows 10 or Windows 11 (64-bit). Other platforms are not supported in V1.1.
  • CPU: Any modern x64 processor. The show engine runs a dedicated 1000 Hz tick thread; 4+ cores are recommended for smooth UI alongside the engine.
  • RAM: 4 GB minimum, 8 GB recommended.
  • GPU: Any DirectX 11-capable GPU for the ImGui renderer.
  • NDI Runtime: The NDI output feature requires the NewTek/Vizrt NDI Runtime to be installed. IDHMFIS ships its own dynamic loader (NdiSender) so it runs safely even without the runtime — NDI simply stays inactive if the DLL is not found. Download NDI Tools free from ndi.video.
  • Build tools: CMake 3.22+ and Ninja (required for building from source).

Installation (Building from Source)

IDHMFIS V1.1 is distributed as source code built with CMake and Ninja.

  1. Clone or extract the repository to a local folder (e.g., C:\IDHMFIS).
  2. Open a Developer Command Prompt for Visual Studio (or any shell with cl.exe and cmake on the path).
  3. Run the following commands:
cd C:\IDHMFIS
cmake -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel
  1. The executable IDHMFIS.exe will be produced in the build\ directory.
  2. Copy or run the executable from the build directory. No installer is required.
Tip: If you encounter linker errors about missing NDI symbols, this is expected. The build does not require the NDI SDK — the runtime library is loaded dynamically at startup.

First Launch Walkthrough

When you first launch IDHMFIS, you will see:

  1. A recovery dialog — only appears if a previous session ended abnormally. If this is a fresh install, click Discard.
  2. The main window — three panels are visible: the Frame Editor (center-left), the Laser Preview (center-right), and the 10-Playback fader strip at the bottom.
  3. Output is OFF by default — for safety, laser output is disabled at startup. Look for the OUTPUT ENABLE button in the Transport bar and click it when you are ready to send output.
  4. NDI status — the Transport bar shows an NDI indicator. If the NDI runtime is installed, streaming begins immediately. Connect NDI Studio Monitor (free) on the same network to see the laser preview as a video signal.

Quick Start: Creating Your First Cue in 5 Steps

  1. Draw something. In the Frame Editor (the large canvas on the left), make sure the Line tool is active (press L or click the line icon in the toolbar). Click two points on the canvas to place a line segment.
  2. Set a color. In the properties panel below the canvas, click the color swatch and choose a color.
  3. Record to a cue. Click the Record KF button at the top of the Frame Editor. A dialog will ask for a cue name. Type a name and press Enter.
  4. Assign to a playback. Drag your new cue from the Cue Library onto one of the 10 playback slots at the bottom of the screen — or click a slot's GO button to activate the most recently recorded cue.
  5. Enable output and GO. Click OUTPUT ENABLE in the Transport bar, then press the GO button on the playback strip. The laser pattern appears in the preview and on any connected NDI receiver.

§ 3Cue System

What Is a Cue?

A cue is a named, self-contained state for the laser system. It defines what color(s) to project, what pattern or shape to draw, where to aim the beam, and how bright to make it. When a cue is activated (by pressing GO on a playback), the engine blends the laser output toward that cue's values over the specified fade time.

Cues are stored in the Cue Library and can be assigned to any of the 10 playback stacks. The same cue can appear in multiple playbacks simultaneously.

Cue Types

Generator Cues

A generator cue uses one of the built-in mathematical pattern generators (Lissajous, Spiral, Thunderbolt, Vortex, Sierpinski, etc.) to produce an animated laser pattern from parameters. Generator cues are infinitely looping and require no manual keyframe animation — just set parameters like Speed, Scale, and Color and the engine does the rest. See Section 6 for a complete list.

Frame / Keyframe Cues

A keyframe cue contains drawn objects (lines, bezier curves, circles, text, etc.) arranged on a timeline. If the cue has only one frame (no animation), it displays a static shape. If it has multiple keyframes, the engine interpolates the objects over time to create smooth animated sequences. Objects with matching IDs morph between frames; objects that appear or disappear fade in and out.

Chaser Cues

A chaser cue is a step sequencer — it cycles through a list of other cues automatically. Each step can have its own hold time and crossfade duration. Chasers can also synchronize to the engine BPM (beat-sync mode) to ensure steps change on-beat at any tempo.

A chaser is created via the Cue Library's New Chaser button. Each step references an existing cue by index. Steps can also override the chaser's global hold/xfade times individually.

The 3 Layers of Every Cue

Every cue — regardless of type — is structured as three independent layers that combine at render time:

LayerControlsDescription
Global Strobe rate, strobe duty, global dim Master intensity and strobe parameters that affect the entire cue uniformly. strobe_rate is in Hz (0 = off). global_dim scales all output brightness for this cue independently of the master fader.
FX Movement effects, color effects, custom DSP blocks An additive stack of effect blocks (pan, tilt oscillators, color rotation, blur, scatter, etc.). FX blocks can be enabled, bypassed, or have a wet/dry mix applied. They run independently of the content layer and can be freely adjusted without touching the keyframe data.
Keyframe Drawn objects (lines, curves, shapes, text) The actual visual content: a list of LaserObject instances at their current interpolated positions. Objects are rendered to a point buffer and passed through the FX stack and Global layer before output.

Cue Timing

Each cue entry in a playback stack carries a full timing block with these parameters:

  • Fade In — seconds from activation to full intensity. 0 = snap (instant).
  • Delay In — seconds to wait before starting the fade in.
  • Hold — seconds to remain at full intensity before auto-advance. 0 = no hold (follows trigger immediately).
  • Fade Out — seconds from deactivation to zero intensity.
  • Wait — seconds after the hold completes before auto-advancing to the next cue. 0 = HALT (manual GO required).
  • Path / Curve — the fade curve shape. Options: Linear, SCurve, EaseIn, EaseOut, EaseInOut, SnapLate, SnapEarly, Expression.

Cue Triggers

What causes a cue to advance? The TriggerType controls this:

  • Halt — manual GO button press required.
  • Follow — auto-advance after a set number of seconds from cue activation.
  • Wait — auto-advance after the cue's hold time completes.
  • Timecode — advance at a specific LTC/MTC/ArtNet TC frame number.
  • MIDI — advance on a MIDI note or CC message.
  • OSC — advance on an incoming OSC message to a specified address.
  • DMX — advance when a DMX channel exceeds a threshold.
  • Audio — advance on a beat, onset, or audio threshold event.

Cue Library

The Cue Library panel (accessible from the View menu) displays all cues in the current project as a scrollable grid. Each cue card shows its name, generator type or preview thumbnail, and color tag.

  • Search: A search box at the top filters cues by name in real time.
  • Duplicate: Right-click a cue and choose Duplicate to create an independent copy.
  • Delete: Right-click → Delete. Cues referenced by active playbacks are not removed from output immediately — the playback finishes its current fade first.
  • Rename: Double-click a cue card name to edit it inline.
  • Properties: Click a cue card to expand its timing, trigger, and layer settings in the Inspector panel.

Cue Numbers (MagicQ-style)

Each cue in a playback has a decimal cue number (e.g., 1.0, 1.5, 2.0). The major number identifies the cue position; the minor number allows inserting sub-cues (1.5 sits between 1.0 and 2.0) without renumbering the entire stack. Jump commands use the major.minor format.

§ 4Frame / Keyframe Editor

Opening the Editor

The Frame Editor is the default primary panel when IDHMFIS starts. It occupies the large left area of the main window. If you have closed it, re-open it via View → Frame Editor. The editor operates in the coordinate space -1.0 (left/bottom) to +1.0 (right/top), matching the laser output coordinate system.

Layer Tabs

Three tabs at the top of the editor switch the active editing layer:

  • Global — set strobe rate (Hz), strobe duty cycle (0–1), and per-cue global dim. Changes here affect the entire cue uniformly.
  • FX — add and configure effect blocks from the FX library. Each block has an enable toggle, a bypass toggle, a wet/dry mix, and its own parameter sliders.
  • Keyframe — the main drawing canvas. All drawing tools work here.

Tool Palette

The vertical toolbar on the left edge of the canvas contains all drawing and selection tools. Click a tool icon or press its keyboard shortcut to activate it.

Object Properties

When one or more objects are selected, the Properties panel (right side of the canvas) shows editable fields:

  • Color — RGB color swatch. Click to open a color picker.
  • Thickness — line stroke weight in pixel units (1.0 default). Higher values produce a brighter, wider beam.
  • Size — radius for circular objects and dot dwell points (normalized canvas units).
  • Dwell — number of extra dwell (repeated) points inserted at vertices and endpoints. Increasing dwell makes corners brighter and helps prevent galvo overshoot artifacts.
  • Density — number of interpolated points per unit length along the object's path. Higher density produces smoother curves at the cost of more points in the output buffer.

Symmetry Modes

The Symmetry selector in the Properties panel applies a live mirror or radial copy to every drawing stroke in real time:

  • None — no symmetry (default).
  • Mirror X — bilateral mirror across the vertical axis.
  • Mirror Y — bilateral mirror across the horizontal axis.
  • Mirror XY — 4-fold mirror (both axes simultaneously).
  • Radial 2/3/4/6/8/12 — rotational n-fold symmetry around the pivot point. Drawing one element replicates it n times evenly around the pivot.

The symmetry pivot defaults to the canvas center (0, 0) and can be moved with the Pivot tool (Y).

Keyframe Animation Timeline

The timeline strip at the bottom of the Frame Editor shows all animation frames for the current cue. The total duration defaults to 4 seconds but can be resized by dragging the right edge of the timeline.

  • Adding a frame: Position the playhead (drag the yellow marker) to the desired time and click Add Frame. The editor takes a snapshot of the current objects as a keyframe at that time.
  • Selecting a frame: Click a frame diamond in the timeline to jump to and edit that state.
  • Deleting a frame: Right-click a frame diamond → Delete Frame.
  • Drag playhead: Click and drag the yellow playhead marker to scrub through the animation in real time.
  • Play/Stop: The transport buttons above the timeline play the animation in a loop.

Interpolation Types

Each keyframe can have its own interpolation type that controls how the engine blends from that frame to the next:

TypeBehavior
LinearConstant-speed blend between frames. Simple and predictable.
Ease In/OutStarts slow, accelerates through the middle, decelerates at the end. Produces natural-looking motion (default).
BezierUser-defined curve with adjustable tangent handles in the value graph view. Maximum control.
Hold / StepObjects snap instantly to the next keyframe values with no interpolation. Good for strobe-style or mechanical effects.

Exporting to a Cue (Record KF)

When you are happy with the content in the Frame Editor, click Record KF (or the record button in the Transport bar while Record Mode is active). A dialog appears:

  1. Type a name for the cue.
  2. Optionally set fade in and fade out times.
  3. Press Enter or click OK.

The new cue appears in the Cue Library and can be assigned to a playback.

Tip: You can also use Record Mode (toggle in the Transport bar) to capture the current output state directly into the active playback as a new cue entry, including live FX and generator parameter adjustments.

§ 5Multiple Playbacks (MagicQ-style)

What Is a Playback?

A playback is an independent cue stack — an ordered list of cues — with its own intensity fader, go/stop controls, and active state. IDHMFIS provides 10 playbacks that run simultaneously and whose outputs are merged (highest intensity wins, using LTP tracking) before reaching the laser output.

This model mirrors the MagicQ and MA lighting desk workflow: each playback behaves like a fader on a physical lighting console. You can run a background ambient loop on playback 1, a beam chase on playback 2, a strobe hit on playback 3, and so on — all independently controllable during a live show.

The 10 Playback Strip

The playback strip is permanently anchored at the bottom of the main window and is always visible, even when other panels are open. Each of the 10 slots displays:

  • The playback name (editable by double-clicking).
  • The name of the currently active cue (green when active, grey when idle).
  • Four control buttons: GO, STOP, CLR, BLIND.
  • An intensity fader.

GO Button

Pressing GO on an inactive playback activates it and begins fading in its first cue (or the cue it last stopped on). On an already-active playback, GO advances to the next cue in the stack (equivalent to Ctrl+G from the keyboard when that playback has focus).

STOP Button

Pressing STOP deactivates the playback, fading out the current cue over its programmed fade-out time. The playback retains its current position in the cue stack — pressing GO again will resume from that point.

CLEAR Button

Pressing CLR (Clear) resets the playback to the beginning of its cue stack (cue position 1.0) and deactivates it. The output fades out immediately. Use this to return a playback to a known starting state between songs or scenes.

BLIND Button

BLIND mode puts the playback into an edit-without-output state. When BLIND is active (the button turns yellow), you can advance through cues, adjust parameters, and program new content without affecting the live laser output. Toggle BLIND off to snap the playback's state to the live output.

Note: BLIND mode does not prevent the playback from contributing to the merged output if it was already active. It only prevents new GO commands from affecting the live output while BLIND is on.

Intensity Fader

The horizontal fader below the buttons controls the overall brightness of all cues on this playback from 0% to 100%. This is independent of the global Master Intensity in the Transport bar. The effective brightness of each laser point is: point brightness × playback intensity × master intensity.

DMX Triggering

Each playback can be mapped to a DMX channel so that an external lighting desk or DMX controller can trigger GO/STOP and control intensity:

  1. Open the Setup window (File → Setup...).
  2. Go to the Network tab.
  3. In the Playback DMX section, assign a universe, channel, and threshold level to the playback.

When the assigned DMX channel exceeds the threshold, the playback fires GO. When it falls below, STOP is triggered. The channel value (0–255) is also scaled to the intensity fader.

Adding Cues to a Playback

To build a cue stack on a playback:

  1. Right-click the playback slot in the strip and choose Open Cue Stack Editor.
  2. Drag cues from the Cue Library into the list.
  3. Reorder by dragging. Set per-cue timing by clicking the timing cells in the list.
  4. Close the editor — changes take effect immediately.

§ 6Generator Cues

How Generators Work

Generators are pure mathematical functions: given a set of parameters and a time value t (seconds since engine start), they return a complete point buffer for that frame. They have no internal mutable state — the same (params, t) inputs always produce identical output. This makes them perfectly reproducible, safe to run on any thread, and trivial to synchronize across multiple machines.

To use a generator cue, create a new cue and select a generator type from the dropdown in the Inspector. The Inspector then shows that generator's specific parameter sliders.

Common Parameters

All generators share a set of global parameters available in the Inspector regardless of generator type:

  • Speed — animation playback speed multiplier. 1.0 = normal, 0.5 = half speed, 2.0 = double.
  • Scale — overall size of the pattern (0.0–1.0, where 1.0 fills the output area).
  • Density / Point Count — total number of output points. Higher values produce smoother output but require more DAC bandwidth.
  • Color A / Color B — start and end colors for gradient-based generators. Many generators blend between A and B across their pattern.
  • Rotation — static rotation offset applied to the entire output (degrees).
  • Pan / Tilt — XY position offset for the entire pattern.

Generator-Specific Parameters

Each generator exposes up to three additional sliders labeled Param A, Param B, and Param C. The Inspector shows the generator's custom labels for these (e.g., for Lissajous: Freq X, Freq Y, Phase). Hover over a slider to see its range and default value.

§ 7NDI Output

What Is NDI?

NDI (Network Device Interface) is a royalty-free protocol developed by NewTek/Vizrt that transmits high-quality video streams over a standard Ethernet LAN. IDHMFIS uses NDI as its primary visual output channel: the laser output is rasterized into a glowing beam video frame and broadcast over your local network where any NDI-compatible receiver can display or capture it.

Common uses for NDI output from IDHMFIS:

  • Monitoring the laser show on a laptop/tablet without physical laser hardware.
  • Feeding a video mixer or VJ software (Resolume, MadMapper, vMix, OBS) to composite laser visuals with other video.
  • Recording the show output as a video file using NDI Studio Monitor's recording feature.
  • Sending a reference feed to a front-of-house operator.

Setting Up NDI Output

  1. Open the Setup window: File → Setup... (or click the gear icon in the Transport bar).
  2. Click the NDI Output tab.
  3. Set your Source Name — this is the name that appears in NDI receiver applications (default: IDHMFIS).
  4. Choose the output Resolution: 480p (854×480), 720p (1280×720), or 1080p (1920×1080). Higher resolutions produce a more detailed preview but require more CPU and network bandwidth.
  5. Set the output Frame Rate (30, 60 fps — default 60).
  6. Ensure the Enable toggle is on.
  7. Click Apply.

The NDI status indicator in the Transport bar turns green when at least one receiver has connected.

Connecting NDI Studio Monitor

  1. Download and install NDI Tools (free) from ndi.video. This includes NDI Studio Monitor.
  2. Launch NDI Studio Monitor on any computer on the same LAN.
  3. Click the source selector drop-down and choose your IDHMFIS source (e.g., IDHMFIS or whatever you named it).
  4. The laser show output appears in the Studio Monitor window in real time.
Tip: If the IDHMFIS source does not appear in the drop-down, check that your firewall allows UDP multicast traffic on port 5353 (used for NDI discovery) and that both machines are on the same subnet.

How the Rasterizer Works

The laser output is a list of X/Y/RGB points, not a traditional video frame. IDHMFIS's built-in rasterizer converts these points into a glowing beam image by painting each point as a lit circle with a surrounding soft glow:

  1. The canvas is initialized to black (all zeros).
  2. For each output point, a solid circle of radius beam_radius is painted in the point's color.
  3. On top of that, a larger, softer Gaussian-blurred halo of radius glow_radius is painted at glow_alpha opacity.
  4. The result is a physically plausible-looking laser beam glow on a dark background.

Beam and Glow Parameters Explained

ParameterDefaultEffect
Beam Radius2.5 pxThe hard-edged beam core radius in pixels (at the output resolution). Increase for a thicker, more visible beam. Decrease for a sharp, precise appearance.
Glow Radius8.0 pxThe radius of the soft outer glow halo. Larger values give a more diffuse, atmospheric look similar to smoke-hazed laser beams in a live venue.
Glow Alpha0.25The opacity of the glow layer (0.0–1.0). Increase for a brighter, more prominent glow; decrease for a clean minimal look.

§ 8Setup Window

Opening the Setup Window

Open the Setup window by selecting File → Setup... from the menu bar, or by clicking the gear icon in the Transport bar. The window is non-blocking (you can keep it open while programming) and changes take effect when you click Apply or change focus out of the affected field.

NDI Output Tab

  • Enable — master toggle for NDI output. Turn off to save CPU when NDI monitoring is not needed.
  • Source Name — the NDI sender name. This is what other applications see when scanning for NDI sources. Changing this requires a restart of the NDI sender (click Apply).
  • Resolution — output video resolution: 480p / 720p / 1080p.
  • FPS — output frame rate. 60 fps is recommended for smooth laser motion preview.

Network Tab

  • OSC Port — UDP port number for incoming OSC messages (default 9000). Change this if port 9000 conflicts with another application. A restart is required for port changes.
  • ArtNet Output IP — the destination IP address for ArtNet DMX output. Use the broadcast address of your subnet (e.g., 192.168.1.255) to reach all Art-Net nodes, or a specific fixture IP for targeted output.
  • ArtNet Enable — enables ArtNet DMX transmission. Requires a valid destination IP.
  • ArtNet Universe Offset — adds an offset to all outgoing ArtNet universe numbers. Use this if your rig already uses universes 0–3 for other purposes.

Beam Params Tab

  • Beam Thickness — the hard-core radius of each rendered beam point in the NDI output (in pixels). See Section 7 for detail.
  • Glow Radius — the outer soft glow halo radius.
  • Glow Alpha — the opacity of the glow layer.

A live preview in the Setup window shows the effect of these parameters on a test point immediately.

§ 9MIDI Learn

Opening the MIDI Learn Panel

Open the MIDI Learn panel via View → MIDI Learn. The panel shows a table of all current MIDI bindings and allows you to create new ones interactively.

Arming a Control for Learn

  1. In the MIDI Learn panel, click Learn next to the engine target you want to map (e.g., Master Intensity, BPM, or a specific playback fader).
  2. The row highlights in yellow, indicating it is armed and waiting for MIDI input.
  3. Move the physical fader or turn the knob on your MIDI controller.
  4. IDHMFIS detects the incoming CC (Control Change) message and records the channel and CC number. The row turns green to confirm the binding.

Bindable Engine Targets

MIDI CC messages can be bound to the following engine parameters:

  • Master Intensity — global output brightness.
  • BPM — live tempo control.
  • Cue Select — selects a cue by CC value (CC value maps to cue index).
  • Playback 1–10 Intensity — individual playback fader levels.
  • Playback 1–10 GO — triggers GO on the specified playback (any non-zero CC value = GO).
  • FX Wet — wet/dry mix for a specific FX block on the active cue.
  • Generator Params — any active generator's Param A, B, or C sliders.

Clearing Bindings

  • Remove a single binding: Click the X button in the binding's row.
  • Clear all bindings: Click the Clear All button at the bottom of the MIDI Learn panel. This is confirmed with a dialog to prevent accidental clearing.

OSC Control

IDHMFIS also accepts Open Sound Control (OSC) messages over UDP for remote control from lighting consoles, touch screens (TouchOSC), and other show control systems. Over 23 OSC routes are available, including:

  • /go — advance active playback.
  • /back — go back one cue.
  • /jump <major> <minor> — jump to a specific cue number.
  • /master <0..1> — set master intensity.
  • /bam/enable <0|1> — toggle BAM safety mask.
  • /quickshow <page> <row> <col> — trigger a Quick Show slot.
  • /livepro/xy <x> <y> — move LivePRO XY position.

Configure the OSC listening port (default 9000) in the Setup window under the Network tab.

§ 10Auto-Save and Recovery

How Auto-Save Works

IDHMFIS automatically saves a backup copy of your project every 2 minutes whenever the project has unsaved changes. You do not need to configure anything — auto-save is always active.

The auto-save file is written to the same directory as your main project file with the extension .autosave appended (e.g., MyShow.idhmfis.autosave). If the project has never been saved (it is still "Untitled"), the auto-save file is written to the system's temporary directory.

The Lock Sentinel

When IDHMFIS starts, it creates a hidden lock file (.autosave_lock) alongside the project. This lock file is removed on a clean shutdown (normal exit). If IDHMFIS crashes or is force-killed while a project is open, the lock file is not cleaned up. On the next startup, IDHMFIS detects the stale lock file and knows that an auto-save from a crashed session exists.

Recovery Dialog

If IDHMFIS detects an unclean shutdown on startup, a recovery dialog appears with two options:

  • Restore — loads the auto-saved version of the project from the previous session. Any work done between the last manual save and the auto-save is recovered.
  • Discard — discards the auto-save and opens the last manually saved version of the project (or a blank project if none exists).

After choosing Restore or Discard, the lock sentinel is cleared and auto-save begins fresh for the new session.

When Is Recovery Cleared?

The recovery sentinel is cleared in two situations:

  1. Clean shutdown — when you exit IDHMFIS normally via File → Exit or the window close button.
  2. Manual save — when you perform a manual save (Ctrl+S), the current state is written to the project file and the auto-save sentinel is refreshed.
Best Practice: Use Ctrl+S frequently during programming sessions. Auto-save is a safety net, not a substitute for regular manual saves.
